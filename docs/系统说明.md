# 系统说明

## 1. 系统概述

一个简化版的在线问卷系统，功能类似问卷星或 Google Forms。V1 完成问卷创建、条件跳转、填写、统计和断点续填；V2 在原系统上续写独立题目、不可变版本、共享、多个命名题库、发布快照冻结、引用查询和同版跨卷统计。注册用户发布后得到形如 `/survey/k3Xp9aQ2` 的链接，填写者仍按原流程一屏一题作答。

## 2. 功能清单

### 2.1 作业需求要求的功能

| 需求 | 实现 |
|------|------|
| 注册、登录 | 用户名 + 密码注册；密码以 bcrypt 哈希存储；登录后获得 JWT 凭证 |
| 用户至少有用户名、密码、注册时间 | `users` 集合的 `username`、`passwordHash`、`createdAt` |
| 只能看到自己创建的问卷 | 所有创作者接口都以 `ownerId` 为条件；访问他人问卷返回 404 |
| 创建问卷：标题、说明、是否匿名 | 编辑页设置标题、说明；分享设置页设置匿名 |
| 发布、设置截止时间、关闭 | 管理页和分享设置页；截止时间实时判断 |
| 每个问卷有可访问的链接 | 8 位随机 slug，链接 `/survey/{slug}` |
| 填写前需要登录 | 默认开启；未登录时引导登录并在登录后回到问卷 |
| 单选题：选项、是否必答 | 支持 |
| 多选题：至少 / 最多 / 必须选 N 项 | `minSelect`、`maxSelect`、`exactSelect` |
| 填空题：文本字数、数字范围、是否整数 | `minLength`、`maxLength`；`min`、`max`、`integerOnly` |
| 跳转：按单选、多选、数字结果跳转，规则可在问卷中设置 | 规则存储在问卷文档中，编辑页可视化设置；单选 3 种、多选 4 种、数字 7 种条件 |
| 按顺序回答、按规则跳转、不合法时提示 | 一屏一题；每点"下一题"由后端校验并计算下一题 |
| 每次填写都保存 | 每次提交插入一份答卷 |
| 多人同时填写、匿名填写、允许多次填写 | 原子操作控制答卷上限；匿名答卷不存身份；"每人一次"由唯一部分索引保证 |
| 统计：单选人数与总人数、多选次数、填空内容、数字平均值 | 一条聚合管道算出全部统计；支持整卷和单题 |

### 2.2 在需求基础上扩展的功能

| 功能 | 说明 |
|------|------|
| 答卷数上限 | 达到上限后链接显示"问卷已收满"，多人同时提交也不会超额 |
| 提交后提示语与外部跳转链接 | 分享设置页配置 |
| 预览 | 创作者在发布前按跳转规则走一遍，不保存答卷 |
| 发布后题目冻结【V2：第二阶段修订】 | 已发布/已关闭问卷的题目、选项、顺序和跳转规则只读；需改题时复制为新草稿 |
| 编辑冲突检测 | 两个窗口同时编辑时，后保存的一方会收到提示，不会悄悄覆盖 |
| 软删除 | 删除问卷后链接失效，答卷保留 |
| CSV 导出 | 选项 ID 转为文字；防 Excel 公式注入 |
| 断点续填 | 登录用户每答一题自动保存进度，下次打开从上次那题继续；30 天未访问自动清除 |
| 我参与的问卷 | 首页列出填写中和已提交（实名）的问卷，可继续填写或查看自己的答卷 |
| 免登录填写（开关） | 为第二阶段预留；关闭登录要求时必须允许重复填写 |
| 独立题目与版本 | 从任意旧版分叉，恢复通过新增版本实现，旧版本不可变 |
| 共享与多个题库 | 支持公开或指定用户共享；每个用户可建立多个命名题库 |
| 引用与跨卷统计 | 本人问卷显示引用明细；同一具体版本按本人问卷汇总，旧答案单列 |

## 3. 角色

| 角色 | 能做什么 |
|------|---------|
| 创作者 | 创建、编辑、预览、发布、关闭、删除自己的问卷；查看统计、导出数据 |
| 填写者 | 通过链接填写问卷；在"我参与的问卷"中继续填写或查看自己提交过的实名答卷 |

同一个账号既可以是创作者也可以是填写者。

## 4. 页面

页面流程和每个页面的详细内容见 [需求分析与界面设计](需求分析与界面设计.md)。

| 页面 | 路径 | 说明 |
|------|------|------|
| 登录 / 注册 | `/login` | 带 `redirect` 参数时登录后回到原页面（只允许站内路径） |
| 我的问卷 | `/` | "我创建的"与"我参与的"两栏；`/#joined` 直接打开"我参与的" |
| 问卷管理页 | `/surveys/{id}` | 链接、答卷数、填写规则；编辑、预览、发布、关闭、统计、删除 |
| 编辑页 | `/surveys/{id}/edit` | 题目卡片与跳转规则区 |
| 预览页 | `/surveys/{id}/preview` | 与填写页外观相同，不保存 |
| 发布 / 分享设置 | `/surveys/{id}/share` | 谁可以填写、何时停止收集、提交之后 |
| 统计页 | `/surveys/{id}/stats` | 整卷 / 单题统计、导出 CSV |
| 填写页 | `/survey/{slug}` | 404、已结束、需登录、已填写过、填写中、提交成功等状态 |
| 我的答卷 | `/me/responses/{id}` | 只读的答卷 |
| 我的题库 | `/question-banks` | 本人题库、本人题目、共享题目与新建入口 |
| 题库详情 | `/question-banks/{id}` | 改名、收录、移出、删除题库 |
| 题目详情 | `/questions/{id}` | 版本历史、分叉/恢复、共享、引用与跨卷统计 |

界面以"答题卡"为视觉语言：印刷红的框线与题号、`[A]` 括号选项、选中时铅笔涂黑；填写页左侧的定位标记显示进度，被跳转跳过的题以斜线标出。

## 5. 系统架构

```mermaid
flowchart LR
    Browser["浏览器：HTML + 原生 JS"] -->|"HTTP / JSON"| Routers
    subgraph backend ["FastAPI 后端"]
        Routers["routers：接口、参数校验"] --> Services["services：业务逻辑"]
        Services --> Repos["repositories：MongoDB 读写"]
        Services --> Pure["logic_engine / answer_validator / rule_checker：纯函数"]
    end
    Repos --> Mongo[("MongoDB：users / surveys / responses / drafts")]
```

分层的约定：

| 层 | 职责 | 约束 |
|----|------|------|
| `routers/` | 接口路径、请求与响应模型、登录依赖 | 不写业务逻辑 |
| `services/` | 状态判断、权限、提交流程、统计结果整理 | 不直接拼 MongoDB 查询 |
| `repositories/` | 全部 MongoDB 查询与更新，每个函数的注释注明对应的访问模式编号 | 只在这一层访问数据库 |
| `logic_engine`、`answer_validator`、`rule_checker` | 跳转计算、答案校验、规则定义校验 | 纯函数，不访问数据库，可单独做单元测试 |

前端不实现任何跳转或校验逻辑，全部调用后端，保证规则只有一份实现。

## 6. 技术选型

| 部分 | 选型 | 理由 |
|------|------|------|
| 数据库 | MongoDB 9.0.2（单机） | 作业要求；问卷题目结构异构、需求会变，文档模型合适（理由详见数据库设计第 11 节） |
| 后端 | Python 3.11 + FastAPI + PyMongo | 类型注解自动生成参数校验和接口文档 |
| 认证 | bcrypt + JWT（PyJWT） | 无状态凭证，不需要额外的会话集合 |
| 前端 | 纯 HTML + 原生 JavaScript，由后端托管 | 作业不要求复杂界面；无需构建工具 |
| 测试 | pytest + FastAPI TestClient + pytest-cov | 接口测试直接调用应用，不需要启动服务 |

## 7. 安全措施

| 风险 | 措施 |
|------|------|
| 密码泄露 | 只存 bcrypt 哈希；`$jsonSchema` 禁止 users 集合出现未定义字段，误写 `password` 字段会被数据库拒绝 |
| 枚举用户名 | 用户不存在与密码错误返回相同提示，并都执行一次哈希比较，耗时相同 |
| 越权访问 | 创作者操作的查询条件都带 `ownerId`；他人问卷与不存在的问卷都返回 404，不暴露是否存在 |
| 伪造作答路径 | 提交时服务端从第一题重新计算路径，路径外的答案一律拒绝 |
| 并发超额、重复提交 | 条件原子更新占名额；唯一部分索引限制每人一份 |
| 匿名泄露身份 | 匿名答卷 `respondentId` 为空，去重标识用 HMAC 生成，无法反推用户；匿名答卷不出现在"我参与的问卷" |
| 外链跳转到恶意脚本 | 结束页外链在数据库层用正则限制为 http / https |
| 登录后跳转到外部网站 | `redirect` 参数只接受站内相对路径 |
| CSV 公式注入 | 以 `= + - @` 开头的文本导出时加单引号 |
| NoSQL 注入 | 管道更新中写入的值用 `$literal` 包裹，以 `$` 开头的文本不会被当成字段引用 |

## 8. 已知限制

- 密钥（`JWT_SECRET`、`HMAC_SECRET`）有默认值，仅用于开发，部署时必须通过 `.env` 修改。
- 没有找回密码、修改用户名等账号管理功能。
- 统计的聚合结果是一个文档，受 MongoDB 16MB 限制；填空内容达到数万条长文本时需要改为分页读取。
- 前端为原生 JS，没有做浏览器兼容性测试，开发时使用 Chromium 内核浏览器。

## 9. 【V2：第二阶段新增】题目复用、版本、共享与跨卷统计

第一阶段的问卷管理、填写、跳转、统计和个人主页全部保留。V2 在同一套系统上增加“题目管理”能力，入口接在主导航、问卷管理页和编辑页中，不建立另一套互不相通的后台。统一页面流程见[需求分析与界面设计](需求分析与界面设计.md)第 5 节。

### 9.1 V2 功能清单

| 新需求 | 系统中的实现 |
|---|---|
| 保存常用题目 | 独立创建题目，或把问卷中的现有题保存为题目身份和第 1 版 |
| 在多份问卷中复用 | 草稿编辑页选择某道题的**具体版本**，把正文复制为本卷快照 |
| 分享题目 | 题主可设为私有、全站登录用户可用、指定用户名可用 |
| 已发布问卷不随改题变化 | 发布后题目、选项、顺序和跳转规则冻结；修改时复制整卷为新草稿 |
| 历史、分叉和恢复 | 版本正文不可变；可从任意旧版分叉；恢复旧版通过创建新版本实现 |
| 不同版本并存 | A 问卷可用 v1，B 问卷可用 v2；创建 v3 不自动替换任何既有问卷 |
| 查看引用 | 本人问卷显示标题、状态和版本；他人问卷只显示去重后的数量 |
| 多个命名题库 | 每个用户可创建、改名、删除多个题库；同一题可进入多个题库 |
| 单题跨卷统计 | 只汇总当前用户自己的问卷中、同一具体版本的可归版答案 |

### 9.2 V2 角色与权限

| 身份 | 可以做什么 | 不能做什么 |
|---|---|---|
| 题目所有者 | 创建版本、从任意旧版分叉、恢复、修改共享、查看引用与本人统计 | 不能覆盖或删除旧版本；不能看到他人的答卷内容 |
| 获共享用户 | 浏览有权使用的版本、选入自己的草稿、复制为自己的独立题目 | 不能在原题版本树中写新版，不能修改原题共享设置 |
| 已有引用但共享已撤销的用户 | 继续使用既有问卷快照，查看来源历史和自己的统计 | 不能再选用、复制或收录该共享题 |
| 无权限用户 | 看不到私有题目，访问统一返回 404 | 不能通过 ID 判断私有题是否存在 |

题目共享和问卷填写权限是两件事：题目详情页控制“谁能把题拿去做新问卷”；分享设置页继续控制“谁能填写这份问卷”。两种权限不互相替代。

### 9.3 V2 页面

| 页面 | 路径 | 主要信息和操作 |
|---|---|---|
| 我的题库 | `/question-banks` | 本人题库、本人创建的题目、共享给我的题目；创建题库和独立题目 |
| 题库详情 | `/question-banks/{id}` | 题目清单、最新版；题库改名、加题、移题、删除 |
| 题目详情 | `/questions/{id}` | 版本树、版本预览、分叉/恢复、共享、引用和同版跨卷统计 |
| 问卷编辑【V2 修订】 | `/surveys/{id}/edit` | 草稿从题库选具体版本、保存现有题、替换版本；发布/关闭后只读 |
| 问卷管理【V2 修订】 | `/surveys/{id}` | 显示题目来源；已发布问卷可复制为新草稿 |
| 问卷统计【V2 修订】 | `/surveys/{id}/stats` | 保留原单卷统计；来源题可跳到具体版本的跨卷统计 |

题库删除只删除分类，不删除题目身份、版本或问卷引用。共享题失权后，在旧题库成员中显示为不可用，用户仍可将它从自己的题库移出。

### 9.4 V2 数据流与架构

```mermaid
flowchart LR
    Bank["题库：itemIds"] --> Item["题目身份 question_items"]
    Item --> Version["不可变版本 question_versions"]
    Version -->|"选择具体版本"| Snapshot["surveys.questions 完整快照"]
    Snapshot --> Fill["原填写 / 跳转 / 校验流程"]
    Fill --> Answer["responses.answers + questionVersionId"]
    Answer --> Cross["本人问卷的同版跨卷统计"]
```

问卷运行时不回查题库或共享权限。填写、预览、跳转重放和原单卷统计继续读取 `surveys.questions`；因此题目后续新增版本、改共享或从题库移除都不会改变已发布问卷。

### 9.5 V2 兼容边界

- 数据层在原四集合外增加 `question_items`、`question_versions`、`question_banks`，原集合和原字段不删除。
- 第一阶段问卷经迁移补 `sourceItemId/sourceVersionId`，题目内容、顺序、规则和 slug 保持原值。
- 新答卷记录实际回答的具体版本 ID；旧答卷没有当时的题目快照，不做推测性补写。
- 旧答卷继续参加原单卷统计；跨卷统计把缺少版本 ID 的答案单列为“无法归版”，不计入分布和平均值。
- V2 明确改变了第一阶段“发布后仍能编辑题目”的规则；其他登录、填写、跳转、校验、统计、导出和断点续填路径保持兼容。
