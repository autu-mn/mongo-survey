# 【第二阶段新增】需求、页面、访问模式与数据演进设计

> 【V2 文档合并说明】本文件是第 1 步形成的阶段性设计记录。其需求口径、页面流程、P24–P34、数据结构和迁移顺序现已完整合并到[《需求分析与界面设计》第 5 节](../需求分析与界面设计.md)。后续修改以该统一主文档为准，本文件保留用于说明当时的设计与核验过程。

状态：第 1–5 步已由学生逐步核验；第 6 步已完成最终回归、文档统一与报告 PDF。需求来源为《大作业一：需求变更(1).md》；下列具体口径来自本次规划会话中学生的选择。

## 1. 第一阶段架构与冲突

第一阶段按“打开、编辑一份问卷”的访问模式，将题目完整内嵌于 `surveys.questions`。`responses.answers` 用问卷内 `questionId` 与 `optionId` 保存答案，另记 `surveyVersion`，但**不保存当时的题目文字、选项文字及整卷快照**。原实现允许发布后更改文字、约束、规则、顺序和隐藏题目；`stats_service`、`export_service`、`me_service` 使用问卷当前题目解释旧答卷。

第二阶段要求题目跨问卷复用、对其他用户共享、版本分叉和恢复、查看引用、跨卷统计。仅复制题目文本不能识别“同一题的同一版本”；仅让多个问卷引用一个可变对象又会让旧问卷随之改变。因此保留问卷内嵌快照作为填写和跳转的独立依据，额外建立不可变的题目版本及来源引用。已发布问卷从第二阶段起冻结题目定义；过去若曾编辑已发布问卷，旧答卷的当时文字无法凭现有数据还原，报告必须如实说明。

## 2. 需求口径与页面流程

| 新需求 | 页面和行为 | 数据归属 |
|---|---|---|
| 保存常用题目 | 题目详情可创建题目及首版；编辑页可将现有题目存入题库 | `question_items` + `question_versions` |
| 共享给别人 | 题主设置私有、全站登录用户可用或指定用户可用；他人可浏览和选用 | `question_items.visibility/sharedUserIds` |
| 旧问卷不受改题影响 | 已发布、已关闭问卷题目只读；复制整卷为草稿后改题 | `surveys.questions` 快照 |
| 历史与恢复 | 显示版本树；从任意旧版分叉；恢复旧版时新增节点 | `question_versions.parentVersionId` |
| 不同版本并存 | 选题时明确选择具体版本，问卷保存来源版本 ID | `surveys.questions.sourceVersionId` |
| 查看引用 | 本人问卷列标题、状态和所用版本；他人问卷只显示数量 | 查询 `surveys.questions` |
| 多个命名题库 | 本人创建、改名、删除题库；将题目加入或移出；选题时浏览具体版本 | `question_banks` |
| 跨问卷统计 | 仅合并当前登录用户自己问卷里，同一具体版本的可归版答案 | `responses.answers.questionVersionId` |

新功能与第一阶段所有页面、入口状态和返回路径的**统一流程图**，以及逐页显示、操作、权限、错误反馈，集中写在[《需求分析与界面设计》第 5 节](../需求分析与界面设计.md)。本文件的 P24–P34 从该逐页设计推导，不再另画一张只含题库的局部流程，以免误以为旧的管理、分享、填写和统计路径会被替换。

新增页面路径为 `/question-banks`（我的题库、我创建的题目、共享浏览）、`/question-banks/{bankId}`（命名题库详情）、`/questions/{itemId}`（版本历史、共享、引用和跨卷统计）。`/surveys/{id}/edit` 内提供选择具体版本的交互；问卷管理页增加“复制为草稿”。题库仅管理题目组织与共享；问卷分享页继续管理填写权限，两者在界面上分开。问卷统计页继续承担单卷统计，跨卷同版统计从题目详情进入。

题目版本保存题型、标题、说明、是否必答、选项和约束；**不保存问卷跳转规则、显示顺序或隐藏状态**，因为跳转目标、顺序和是否显示取决于具体问卷。选入问卷时保留该版本的选项 ID，生成问卷内新的 `questionId`，并复制内容为问卷快照。关联版本的草稿题目不能直接改内容：题主可从其源版本创建新版并替换本草稿引用；使用他人共享题目者可另存为自己的新题目。未关联的草稿题目继续支持第一阶段的原位编辑。

新建题目默认私有；题库也仅由创建者管理。分享权限附着在题目身份上，适用于其所有版本。撤销分享只禁止其他用户新的选用，已存在的问卷快照不受影响。跨卷统计不因题目共享而暴露他人的答卷。“他人使用数量”按去重后的问卷数计算，同一问卷多次选用同一题目仍计为一份问卷。问卷软删除后不出现在引用列表和跨卷统计中；既有答卷的原有保留规则不变。

## 3. 新增集合和现有集合扩展

| 集合 | 主要字段 | 原子边界及索引 |
|---|---|---|
| `question_items` | `_id`, `ownerId`, `visibility`（private/public/selected）, `sharedUserIds`, `originSurveyId?`, `originQuestionId?`, `createdAt`, `updatedAt`, `schemaVersion` | 身份、共享设置单文档更新；`ownerId+createdAt` 列表索引，公开及定向分享检索索引，问卷来源唯一部分索引（迁移与保存现有题目共用） |
| `question_versions` | `_id`, `itemId`, `versionNo`, `parentVersionId?`, `type`, `title`, `description`, `required`, `options`, `constraints`, `createdAt`, `schemaVersion` | 插入后不可改内容；`itemId+versionNo` 唯一索引；按版本号倒序查最新版，按 `itemId` 取历史 |
| `question_banks` | `_id`, `ownerId`, `name`, `itemIds[]`, `createdAt`, `updatedAt`, `schemaVersion` | `$addToSet/$pull` 原子维护成员；`ownerId+name` 唯一索引和本人列表索引 |
| `surveys.questions[]` | 原字段不删；新增可选 `sourceItemId`、`sourceVersionId` | 本地题目 ID 继续供规则、答卷与草稿使用；新增 `questions.sourceItemId+ownerId+deletedAt` 引用查询索引 |
| `responses.answers[]` | 原字段不删；新增可选 `questionVersionId` | 仅可确认来源的新答案写此字段；新增 `answers.questionVersionId+surveyId` 跨卷统计索引 |

`schemaVersion` 升为 2；MongoDB 校验器和读取路径在迁移期兼容版本 1 文档。`drafts` 的题目 ID 和问卷版本机制保持原样。题目版本号分配通过 `itemId+versionNo` 唯一索引与冲突重试实现；一个题目可从任意历史版本产生子节点，因此版本号表示创建次序，`parentVersionId` 才表示衍生关系。恢复旧版也插入新版本，不改旧节点。

## 4. 第二阶段访问模式与接口

以下编号接在第一阶段 P1–P23 之后。所有新接口需登录，响应字段沿用驼峰式命名；授权失败不暴露私有题目是否存在。

| 编号 | 页面操作与接口组 | 查询或写入及索引依据 |
|---|---|---|
| P24 | 我的题目、共享题目列表：`GET /api/question-items` | 按 `ownerId`、`visibility` 或 `sharedUserIds` 检索，分页 |
| P25 | 创建题目：`POST /api/question-items` | 可直接提交题目内容，也可带有权访问的 `sourceVersionId` 复制共享题为本人新题目身份；写首个不可变版本，复用现有题型/约束校验。复制不改变原题的版本树或跨卷统计口径 |
| P26 | 版本树：`GET /api/question-items/{itemId}/versions` | `itemId+versionNo` 有序读取 |
| P27 | 分叉/恢复：`POST /api/question-items/{itemId}/versions` | 请求含 `parentVersionId` 和内容；恢复按钮复制旧版内容调用同一接口；仅题主可写 |
| P28 | 共享设置：`PUT /api/question-items/{itemId}/sharing` | 题主更新 `visibility/sharedUserIds`，指定用户必须存在 |
| P29 | 题库 CRUD 与成员：`/api/question-banks` | 本人题库及题目身份引用，成员使用 `$addToSet/$pull` |
| P30 | 从题库选题：`POST /api/surveys/{id}/questions/from-library` | 草稿所有者 + 版本访问权限检查，复制内容并写来源 ID；沿用 `If-Match` |
| P31 | 保存已有题目：`POST /api/surveys/{id}/questions/{qid}/save-to-library` | 以当前快照创建独立身份/版本；若已关联则避免重复创建。对已发布问卷只补来源元数据，不改题目内容，旧答案不补版本 ID |
| P32 | 复制问卷：`POST /api/surveys/{id}/copy` | 仅所有者；新草稿、新 slug、答卷数归零，保留题目快照与版本引用 |
| P33 | 引用查询：`GET /api/question-items/{itemId}/usage` | 按 `questions.sourceItemId` 查；本人返回列表，他人仅聚合数量 |
| P34 | 版本跨卷统计：`GET /api/question-items/{itemId}/versions/{versionId}/stats` | 以 `answers.questionVersionId` 和本人 `surveyId` 过滤；旧答案单列未归版数 |

第 2 步实现数据结构与迁移，第 3 步实现 P24–P28，第 4 步实现 P29–P33 和已发布冻结，第 5 步实现 P34 与页面。共享被撤销后，曾将该题用于本人未删除问卷的用户仍可查看来源历史和本人统计，但不能新选题或复制源版本。新路由先以服务层完成权限判断，再通过仓储层访问 MongoDB；现有 `logic_engine`、`answer_validator`、`rule_checker` 继续负责跳转和校验。

## 5. 迁移与兼容顺序

1. 备份现有 MongoDB；记录四个旧集合文档数、问卷题目数、答卷数和现有 schemaVersion 分布。脚本提供检查模式，先输出待建题目身份/版本及异常，不写库。
2. 安装兼容旧字段的新校验器和索引。对每个旧问卷题目，以 `(surveyId, questionId)` 作为迁移来源键创建**单独**的私有题目身份和第 1 版；有来源键唯一索引，重复运行复用同一身份/版本。保留原题目与选项 ID，给问卷中的题目补来源 ID，不改内容及规则。
3. 已有 `responses.answers` 保持原样，不事后补写无法核实的版本 ID。迁移后新提交的关联题目答案写入 `questionVersionId`；未关联的草稿题目在发布前建立私有版本并附来源，确保发布后题目可冻结且新答卷能归版。
4. 迁移后重新核对旧集合数量、问卷题目顺序/内容、答卷内容、可打开的链接、原统计与导出；新建身份和版本数量应等于迁移时现有题目数量。遇到中途失败可重跑，不删除旧集合或旧字段。对于曾在发布后编辑过的历史问卷，只能保存迁移时的内容，不能宣称还原了过去的题目文字。

## 6. 第 1 步核验范围

本步只保存基线和设计文档，不修改数据库、schema、后端或前端代码。学生核验重点：页面流程是否符合使用习惯；题目身份、版本与问卷快照的关系；共享与统计权限；旧数据不可归版的解释；P24–P34 是否覆盖八条新需求。确认后才进入第 2 步。
